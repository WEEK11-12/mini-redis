# D-0001: 사용자 주도·단계별 반복 진행

- 카테고리: 프로젝트 진행
- 상태: 채택
- 작성일: 2026-11-17
- 결정일: 2026-11-17
- 결정자: 사용자
- 확인 근거: 사용자가 제시한 프로젝트 진행 원칙과 컨벤션 수정 요청
- 관련 문서: [과제 원문](../assignment.md), [컨벤션 초기안](../conventions.md)
- 대체 관계: 없음

## 배경

사람이 목표와 요구사항을 생각하고, 선택지를 판단하고, 결과를 확인하는 주체가 된다. 에이전트는 비교 자료·구현·검증을 제공하여 요구사항 정의 → 설계 → 검증 → 구현 → 검증의 반복 실행을 돕는다. 사람의 판단과 에이전트의 실행 지원을 구분하는 것을 프로젝트 진행 원칙으로 삼는다.

Redis 이론 학습은 완료했다고 사용자가 확인했다. 이 사실은 구현·테스트 완료나 기술 선택 확정을 뜻하지 않는다.

## 사용자가 정한 원칙

1. `docs/assignment.md`를 바탕으로 구현을 진행한다.
2. 학습과 서비스 제작 목표를 분명히 하고, 전체 구현 단계는 유동적인 계획으로 유지한다.
3. 각 단계에서 요구사항 정의 → 설계 → 검증 → 구현 → 검증을 반복하며, 수정이 필요하면 앞 단계로 돌아간다.
4. 요구사항은 사용자가 먼저 상세히 생각하고 AI 초안과 대조·보완한다.
5. 설계는 가능한 옵션과 비교를 제공받은 후 사용자가 직접 선택한다.
6. 구현은 매 단계의 결과물을 사용자가 직접 확인한다.
7. 전체 그림을 보되 인터페이스 중심으로 모듈 간 의존성을 줄인다.
8. 사용자 결정은 `docs/decisions/` 등 구분된 공간에 기록한다.
9. 에이전트 전용 맥락·인계 문서는 Git에서 제외하고, AI가 작성했더라도 사람이 읽는 진행·결과 문서와 구분한다.
10. 요구사항 정리보다 문서·코드 컨벤션 정리를 먼저 한다.

## 결정의 범위

이 결정은 진행 방식에 관한 것이다. 컨벤션의 세부안 전체, 목표·범위·기술 스택·통신 방식·동시성 구조·선택 기능의 채택까지 뜻하지 않는다.

## 이유와 영향

- 사용자가 목표·요구사항·설계의 판단 주체로 참여하고 에이전트는 반복 실행을 지원한다.
- 작은 결과물을 확인하고 실패·변경에 따라 되돌아갈 수 있도록 한다.
- 요구사항·설계를 전체 범위로 한 번에 확정하지 않는다.
- 목표·범위·기술 스택·통신 방식·동시성 구조·선택 기능은 이 기록으로 결정하지 않는다.

## 재검토 조건

과제 제약이나 사용자의 진행 목표가 달라지거나, 문서·확인 절차가 작은 단계의 실행을 지나치게 막는 경우 사용자와 조정한다.
