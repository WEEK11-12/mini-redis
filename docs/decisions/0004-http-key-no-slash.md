# D-0004: HTTP 키에서 슬래시 제외

## 배경과 판단 기준

[D-0003](0003-http-response-contract.md)은 비어 있지 않은 문자열 키와 `/keys/{key}` 경로를 정했지만, 키의 URL 표현과 추가 제약은 후속 설계로 남겼다. 슬래시가 키 데이터인지 경로 구분자인지 구별하는 추가 처리를 이번 HTTP 연결 범위에 넣지 않는다.

## 결정과 영향

- HTTP API가 받는 키에는 슬래시(`/`)를 허용하지 않는다. 이는 **외부 API의 입력 제약**이며, 2단계 저장소의 문자열 키 계약을 변경하지 않는다.
- 클라이언트가 키를 받는 편의 함수를 제공한다면 URL을 만들기 전에 빈 키와 슬래시 포함 여부를 검사해 즉시 오류를 알릴 수 있다. 단, 클라이언트 검사는 우회 가능하므로 서버에서도 HTTP 경계의 키를 검증해야 한다. 필수 클라이언트 라이브러리를 새로 요구하는 결정은 아니다.
- 구분 가능한 잘못된 키 요청은 [D-0003](0003-http-response-contract.md)의 잘못된 입력 계약(`400`·공통 오류 본문)에 맞춘다. 원시 슬래시와 인코딩된 슬래시가 라우터를 통과하는 방식 및 경로 불일치 요청의 취급은 3단계 설계·통합 TC에서 정한다. 현재 특정 HTTP 도구의 동작은 확인되지 않았다.
- 공백·유니코드·기타 특수 문자의 추가 허용 범위, URL 인코딩, 구체적 오류 코드는 아직 확정하지 않는다.

## 재검토 조건

슬래시를 포함한 키가 실제 사용 사례에 필요하거나, 선택한 라우팅 방식에서 키 표현·오류 계약을 일관되게 제공하기 어려우면 재검토한다.
