# 요구사항과 인수 조건

상태: 기본 동작은 사용자와 합의. U1~U4 기본 저장소·TTL·능동 청소 테스트를 통과했다. R-07의 합의한 U5 필수 검증도 통과했다. 모든 스케줄의 안전성을 증명한 것은 아니며 R-10 실제 서버 진입점 연결은 U6에 남아 있다. 과제 원문 요약은 [assignment.md](assignment.md)를 따른다. 아래 세부 정책은 프로젝트 선택이며 과제 원문의 강제 조건이 아니다.

| ID | 요구 동작 | 출처 | 인수 조건 |
| --- | --- | --- | --- |
| R-01 | 해시 테이블 직접 구현 | 과제·합의 | FNV-1a 64비트, 버킷 배열과 연결 리스트 체이닝. 다른 키가 충돌해도 구분 |
| R-02 | 문자열 저장·조회·삭제 | 과제·합의 | 덮어쓰기는 최신 값과 같은 키 수. 없는 키 조회 None, 삭제는 bool |
| R-03 | 입력 규칙 | 합의 | 빈 키·값, 공백·줄바꿈 등 원문 유지. UTF-8 키 최대 1 KiB, 값 최대 1 MiB. 문자열 외 입력 거부 |
| R-04 | 테이블 확장 | 합의 | 초기 16버킷, 신규 키로 0.75 초과 시 2배. 13번째 신규 키에서 32버킷. 기존 키 덮어쓰기로 확장하지 않음 |
| R-05 | TTL 저장·접근 만료 | 과제·합의 | 양의 정수 밀리초. 생략은 무기한, 일반 덮어쓰기는 TTL 제거. 현재 단조 시간 >= 만료 시각이면 반환 금지 |
| R-06 | 접근 없는 만료 키 회수 | 과제·합의 | 청소 스레드가 목표 간격 100ms로 실행. 회차당 최대 100키·100버킷 방문, 위치 이어가기 |
| R-07 | 동시 접근 일관성 | 과제·합의 | 단일 프로세스에서 모든 저장소 접근·청소가 같은 락 사용. 삭제·확장·청소가 테이블과 커서를 손상하지 않음 |
| R-08 | 외부 HTTP API | 과제·합의 | POST /set, /get, /delete, JSON 요청·응답. 상세는 API 문서 |
| R-09 | 잘못된 입력의 안전한 거부 | 합의 | TTL null·0·음수·소수·문자열·bool, 누락 필수값·미정의 필드 등 거부. 입력 오류 시 기존 값·TTL 유지 |
| R-10 | 생명주기 | 합의 | 진입점에서 저장소·락·청소 생성 후 서버 실행. 종료 신호 후 청소 종료 확인. import에 실행 부작용 없음 |
| R-11 | 명시적 무효화 | 과제·합의 | /delete로 기존 값 제거. 없는 키 삭제는 정상 결과 false |
| R-12 | 외부 API 응답 캐싱 실증 | 과제 | 별도 데모에서 원본 호출→캐시 저장→재사용·만료·무효화 검증. 구체 원본·데이터는 해당 단위에서 합의 |
| R-13 | 정확성·성능 검증 기록 | 과제·합의 | 단위·HTTP 기능·동시 요청 테스트와 캐시 미사용/Miss/Hit 비교. 실제 명령·결과·실패·수정 기록 |

## 범위와 상태

초기 구현에서 영속성과 재시작 복구는 제외한다. 종료하면 데이터가 사라진다. 실제 Redis 전체 자료형·RESP·트랜잭션·분산 저장소를 구현하지 않는다.

문서가 있다고 구현 완료가 아니다. 단위별 상태·인계는 [WORKLOG](../WORKLOG.md), 검증과 추적은 [TESTING](TESTING.md)을 따른다.

## 해당 구현 단위에서 추가 확인할 경계

기본 구조와 위 동작은 확정했다. 다음은 확정값을 꾸며 넣지 않고 관련 단위 전에 확인한다.

TTL에는 별도 기간 상한을 두지 않는다. 내부 시간은 정수 나노초로 계산한다. len(store)는 만료 잔여 노드를 포함한 보관 노드 수이고 만료 키 삭제는 False를 반환하며 노드를 정리한다.

남은 항목:
- JSON 중복 필드·잘못된 Unicode 등 일반 입력 범위를 벗어난 사례의 응답.
- 메모리 부족·확장 실패의 복구 보장 범위. 잘못된 입력의 상태 보존과 프로세스 메모리 고갈은 다른 문제다.
- 연결·대기열·타임아웃·전체 저장 용량 제한, 측정 부하와 성능 판정 기준.

미정 항목과 무관한 첫 단위의 정상 문자열 저장·조회·삭제·충돌 검증부터 진행할 수 있다.
