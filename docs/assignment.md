# Mini Redis 과제 요구사항

사용자가 제공한 과제 문서의 범위와 품질 요구를 정리했습니다. 프로젝트에서 선택한 수치나 라이브러리를 과제 원문 요구와 혼동하지 않습니다.

## 기본 요구

- 해시 테이블을 활용해 키-값 저장소를 직접 구현합니다.
- 외부 프로그램이 저장소를 사용할 수 있어야 합니다.
- 해시 테이블의 설계 원리와 주요 함수의 동작을 설명할 수 있어야 합니다.
- 사용 기술은 자유이며 AI를 적극 활용해 구현하되 핵심 로직은 이해하고 설명해야 합니다.

## 중점 검토

- 동시성 문제를 막기 위한 구조
- 보관 기간이 지난 값을 요청했을 때의 처리
- 외부에서 사용하기 쉬운 API 구조
- 사용자가 저장된 데이터를 무효화하는 방법

서버 장애에도 데이터를 보존하는 영속성은 선택사항입니다.

## 품질 확인

- 저장·조회·삭제 기능을 단위 테스트로 검증합니다.
- 외부에서 사용하는 기능 테스트를 수행합니다.
- 간단한 API 응답을 Mini Redis에 저장해 활용합니다.
- 중요한 경계·오류 상황을 고려합니다.
- 저장소 사용 전후의 성능을 같은 조건에서 비교합니다.

## 과제 요구와 프로젝트 선택

Python·Flask·Waitress, FNV-1a, 체이닝, 버킷 16개, 적재율 0.75, HTTP, 단일 프로세스·공용 락, 만료 검사 초기 수치는 과제에서 강제한 값이 아니라 우리가 선택한 설계입니다. 이유와 미결정 사항은 [설계 기록](https://github.com/jye-1123/mini-redis/blob/study-jye/study/07-project-decisions.md)에 따로 남깁니다.
