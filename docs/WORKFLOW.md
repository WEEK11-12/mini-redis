# 협업과 검증 기록

## 함께 작업할 때

- Mini Redis와 Mini DBMS는 담당자가 각자 구현합니다. 두 파트가 만나는 데이터 형식·호출 방식은 연결 작업 전에 함께 정하고 해당 저장소 문서에 남깁니다.
- 한 작업 단위에는 목적, 설계 이유, 변경 내용, 실행한 테스트, 남은 문제를 적습니다. 커밋·푸시는 담당자의 요청과 확인을 거쳐 진행합니다.
- 서로의 파트를 리뷰할 때는 파일·동작·재현 입력을 지정해 질문이나 문제를 남깁니다. 작성자는 판단 근거와 수정 결과를 답하고, 리뷰어는 재검증 결과를 남깁니다.
- 테스트가 실패했다면 실패한 사실을 지우지 않고, 원인 가설과 수정 전후 결과를 함께 남깁니다.

## 기능별 기록 양식

작업할 때마다 아래 항목을 복사해 PR 설명이나 작업 기록에 채웁니다. 실행하지 않은 테스트는 `미실행`으로 표시합니다.

```md
### 기능:
- 기대 동작과 사용 예:
- 설계 선택과 이유:
- 확인할 경계값·실패 조건:
- 실행 환경과 명령:
- 결과(기대/실제):
- 발견한 문제, 원인 가설, 수정 및 재검증:
- 부하 테스트 조건(입력 규모·동시 연결 수·반복 횟수)과 결과:
- 리뷰 질문·의견과 답변:
- 남은 한계:
```

성능 비교는 동일한 입력과 반복 횟수로 수행하고, 캐시가 비어 있는 경우와 채워진 경우를 구분해 기록합니다. 측정값이 나오기 전에는 성능 향상을 주장하지 않습니다.
