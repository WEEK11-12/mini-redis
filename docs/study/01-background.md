# 1. Redis는 왜 등장했나 (역사와 배경)

> - 디스크 기반 DB의 한계: 반복되는 조회, 디스크 I/O 비용
> - 캐시의 등장: 자주 쓰는 데이터를 메모리에 키 → 값으로 저장 (Memcached)
> - Memcached의 한계: 구조 없는 값, 디스크 저장 불가, 일부만 수정하기 어려움
> - Redis의 탄생(2009): 메모리 속도 + 서버가 이해하는 자료구조 + 선택 가능한 영속성
> - 이후의 흐름: 캐시를 넘어 세션, 랭킹, 큐 등으로 확장, DB와의 공존

---
## 반복 조회와 디스크 I/O
- **문제점** : 반복되는 DB 조회 → **DB는 같은 결과를 반복해서 찾아서 전달**
  - 데이터가 디스크에서 읽는 비용도 반복됨
- **캐싱** : 자주 요청되는 결과를 메모리에 보관해 재사용
- **핵심** : 반복 조회의 부담을 원본 DB와 분리할 이유가 있음
  - 디스크 기반 DB가 조회할 때마다 반드시 디스크 읽기를 하는 것은 아님
  - DB도 메모리 캐시를 사용함 → DB가 항상 병목이라는 것은 아님

---

## Key:Value 캐시
- **key**: 어떤 데이터를 찾을지 나타내는 이름
- **value** : 재사용할 데이터
- `key:value` 구성의 적합성 : "이전에 구한 결과를 같은 요청에서 바로 찾기"에 적합
  - 모든 캐시가 반드시 단순한 `key:value` 저장소인 것은 아님
  - 다만, **같은 입력으로 같은 결과를 찾는 용도** → `key:value` 형태가 가장 간단하고 빠름

---

## Memcached
- 목적 : 키에 대응하는 값을 저장하고 꺼내는 데 초점을 둠

#### 한계 1: 구조 없는 값
- 키-값만 알고 있고, **자료구조를 이해하지는 못함**
  - `user:7`에 사용자 정보를 하나의 값으로 저장 → `user`의 `name`만 바꾸기 불가능 (내부의 여러 필드 이해 x)
  - `user` 전체를 업데이트 하거나, 변경되는 필드마다 따로 `key:value`로 값을 저장해야 하는 불편함 존재
- Redis와 비교
  - Redis는 서버가 **값(value)의 내부 구조를 알고, 그 일부를 다룰 수 있음**
  - Hash 같은 자료구조를 이해함 → 특정 필드를 바꾸는 명령을 내보낼 수 있음.
    

#### 한계 2: 디스크 저장 불가
- Memcached는 기본적으로 메모리 캐시임
  - 서버가 재시작 → **저장된 값이 사라짐**
  - 원본 DB에서 다시 가져와 캐시를 채우는 용도를 전제로 함
- Redis와 비교
  - Redis는 디스크에 기록하는 **영속성 기능**을 선택할 수 있음
  - 재시작 후 데이터를 복구해야 하는 때에 사용 가능
  - _어떤 장애에도 데이터가 전혀 유실되지 않는 것은 아님_
    - 기록 방식에 따라 마지막 기록 이후 변경 소실 가능

---

## Redis

#### Redis의 탄생
- 실시간 로그 분석 서비스가 겪던 데이터 처리 문제를 풀기 위해 만들어짐
  - 단순히 Memcached의 기능을 늘리기 위한 취지에서 출발한 것이 아님
- 배경 :
  - 방문 기록이 계속 들어오고, 그 결과를 빠르게 다뤄야 하는 작업
  - 기존 DB 방식으로는 원하는 성능을 내기 어려웠음
- 핵심 발상 :
  - 데이터를 메모리에서 빠르게 다루되, 서버에 단순한 값 보관 이상의 명령을 제공하는 것
  - 값을 DB에서 꺼내 계산 후 다시 저장하는 대신, 저장소에 값 조작 명령을 직접 내림
  - 이에 따라 Redis의 자료구조와 그에 대한 명령이 중요해짐

#### Redis의 발전 흐름
- Redis가 값에 대한 명령과 자료구조 제공 → 이미 만들어진 결과를 보관하는 일 외에도 사용 가능
- **세션** : 로그인 상태를 일정 시간 보관
- **랭킹** : 점수 순서를 관리
- **큐** : 처리할 작업을 순서대로 담음
- 주의사항 : Redis가 원본 DB를 항상 대체하는 것은 아님
  - 복잡하게 조회하거나 오래 보관해야 하는 데이터는 DB가 적합 (예 : 상품, 주문)
  - 자주 읽는 결과나, 빠르게 갱신할 상태를 Redis에서 다루는 식으로 DB와 함께 사용
