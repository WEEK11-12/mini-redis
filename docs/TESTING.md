# 구현 단위와 검증 계획

U1의 T-01~T-06은 PASS, 나머지는 NOT RUN이다. [U1 실행·실패·재검증 기록](verification/U1-storage.md)을 함께 읽는다. 문서 검증과 제품 테스트를 구분한다. 요구 ID는 [REQUIREMENTS](REQUIREMENTS.md), 결과는 [WORKLOG](../WORKLOG.md)와 [기록 양식](WORKFLOW.md)에 연결한다.

## 진행 순서

| 단위 | 범위 | 관련 요구 | 진행 조건 |
| --- | --- | --- | --- |
| U1 | 저장·조회·삭제·충돌 삭제 | R-01, R-02, R-11 | 로컬 구현과 6개 테스트 통과, 사용자 검토 대기 |
| U2 | 입력·FNV 검산·확장 | R-01, R-03, R-04, R-09 | 기대 결과·경계 테스트 함께 확인 |
| U3 | TTL·접근 만료 | R-05, R-09 | 큰 TTL·만료 키 삭제 의미 등 남은 경계 확인 |
| U4 | 능동 청소·커서·종료 | R-06, R-10 | 삭제·확장 중 진행과 종료 테스트 확인 |
| U5 | 동시 저장·조회·삭제·청소 | R-07 | 락 자체는 초기 저장소 구조부터 적용, 여기서 겹침 검증 |

## U1 — 합의한 첫 단위

| 테스트 ID | 입력·상황 | 기대 결과 | 잡으려는 오류 |
| --- | --- | --- | --- |
| T-01 | 새 키 저장 후 조회 | 동일 문자열 | 저장·탐색 연결 실패 |
| T-02 | 같은 키 덮어쓰기 | 최신 값, 키 수 유지 | 같은 키를 중복 노드로 추가 |
| T-03 | 저장 키 삭제 후 조회 | None | 체인에서 실제 제거하지 않음 |
| T-04 | 없는 키 조회·삭제 | None / False, 상태 유지 | 없음과 빈 값 혼동·불필요 예외 |
| T-05 | 같은 버킷의 서로 다른 키 저장 | 각각의 값 | 버킷 번호만 보고 덮어쓰기 |
| T-06 | 충돌 체인의 첫·중간·끝 삭제 | True, 나머지 모두 조회 가능 | 연결 끊김·잘못된 헤드 변경 |

충돌은 계산으로 확인한다. 키가 비슷하게 생겼다는 이유로 충돌이라고 하지 않는다. 독립적으로 확인한 FNV 벡터는 U2에서 검사한다. 미구현 import 실패만 보고 기능 실패를 재현했다고 주장하지 않는다.

| T-14 | R-08, R-09 | Flask 단위 호출로 정상·400·413·415, 미정의 필드와 상태 보존 |

후속 테스트의 구체 입력·반복 수·통과 조건은 해당 단위에서 사용자와 확정한다. 표에 있다는 이유로 일괄 구현하지 않는다.

## 검증 절차

테스트 목적·예상 결과를 설명 → 작은 실패를 실행해 원인 확인 → 최소 구현 → 재실행 → 결과·실패·수정을 기록 → 사용자 확인 후 다음 단위. 버그가 없는데 실패 이력을 만들어내지 않는다.

Python 3.13.14와 표준 unittest를 사용했다. 현재 실행 명령은 `python -m unittest discover -s tests -v`다. Flask·Waitress 설치와 서버 검증은 미실행이다. 성능 결과에는 입력 크기·동시 요청·읽기쓰기 비율·워밍업·표본·지연 분포·실패율·환경을 기록한다. 계획 수치를 측정 결과로 표현하지 않는다.
