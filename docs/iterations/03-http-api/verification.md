# 3단계 검증 기록 — HTTP 연결과 응답 재사용

- 상태: 3단계 범위 독립 검토 승인 — 최신 HTTP 32개·저장소 24개 실행 통과
- 근거: [요구사항](requirements.md), [TC 목록](test-cases.md), [구현 기록](implementation.md)

## 실행 환경·결과

저장소 루트에서 Python 3.14.5로 실행했다. 제품 코드 작성 전 `python3 -m unittest discover -s tests -p 'test_http_api.py' -q`는 구현 모듈 부재로 29개 실패(예상 RED), 저장소 단위 24개는 통과했다.

| 범위 | 명령 | 구현자 관찰 결과 | 독립 검토 |
| --- | --- | --- | --- |
| `TC-03-I-001`~`023`, `TC-03-E-001`~`006`의 최초 테스트 코드 29개 | `python3 -m unittest discover -s tests -p 'test_http_api.py' -q` | 최초 리비전에서 29개 실행, OK (같은 명령 재실행에서도 29개 OK). 이후 독립 검토에서 3건의 경계 결함을 발견했으므로 현재 리비전의 전체 통과 근거로 사용하지 않음 | 수정 요청 |
| 2단계 저장소 회귀 | `python3 -m unittest discover -s tests -p 'test_store.py' -q` | 24개 실행, OK | 대기 |
| 문법·변경 형식 | `python3 -m compileall -q mini_redis examples`; `git diff --check` | 둘 다 종료 코드 0 | 대기 |

## 독립 검토 지적과 제한 재점검

최초 독립 검토에서 15개 추가 probe 중 10개 통과·5개 실패했으며, 실패는 R1(캐시 리다이렉트), R2(긴 선행 0 길이), R3(`stored` 숫자 1/1.0)로 묶였다. 2초 읽기 타임아웃 경로는 독립 probe에서 정상 관찰됐다. 판정은 **수정 요청**이다.

R1~R3만 수정하고 `tests/test_http_api.py`에 세 가지 회귀 테스트를 추가했다. 수정 전 이 3개는 실패(3 failures, 1 error), 수정 후 `python3 -m unittest discover -s tests -p test_http_api.py -k test_i_016 -k test_i_017 -k test_e_001 -k test_e_003 -k test_e_004 -k test_e_005 -q`에서 해당 경계와 영향받는 정상 사례 **9개 OK**. `python3 -m compileall -q mini_redis/http_api.py examples/client.py tests/test_http_api.py` 및 `git diff --check`는 종료 코드 0. 이미 확인한 2단계 저장소 검사 및 나머지 HTTP 케이스는 **이번 수정 후 재실행하지 않았다**.

검증 담당의 제한 재검토는 R1~R3 각각 **승인**이다. 실제 HTTP·별도 CLI probe는 선언 8개/열거 8개 모두 통과, 실패 0으로 집계됐으며, 긴 선행 0의 본문 없는 초과 길이 조기 거부·캐시/원본 리다이렉트 차단·숫자 1/1.0 거부와 `true` 대조군을 포함한다. 제품 소스와 테스트 파일의 검토 해시가 현재 파일과 일치함을 확인했다. 이 판정은 첫 검토의 비영향 범위 결과와 구현자의 수정 후 9개 점검을 재사용한 **당시 수정 경계 승인**이었다. 그 시점에는 현재 리비전의 HTTP 전체 32개 또는 저장소 24개를 새로 실행하지 않았으며, 아래 최신 리비전 전체 인수 검증에서 별도로 실행했다. 이 문서 갱신은 검토된 소스 스냅샷 이후의 상태 기록으로, 제품 코드 변경은 없다.

테스트 코드의 TC ID 연결은 `test_i_###`·`test_e_###` 번호에 대응한다. 최초 독립 코드 검토에서는 키 길이 상한 부재, 저장소 버킷 비조작과 단일 스레드 구조를 확인했다. 읽기 타임아웃 경로도 최초 독립 probe에서 확인됐지만 수정 후 재실행하지 않았다. 파싱 전 거부·중간 계층의 점 구간 정규화는 계약 보장 밖이다. 외부 포트 고정 수동 시연 및 성능 비교는 실행하지 않았다.

## 최신 리비전 전체 인수 검증

검증 담당이 앞선 코드 검토와 수정 경계 승인을 바탕으로 Python 3.14.5, 저장소 루트에서 아래 공식 명령을 **최신 리비전으로 각각 한 번** 실행했다. 원본 로그와 목록·결과 집계는 검증 담당의 로컬 `stage03-final-review/` 아티팩트에 있다. 실행 전후 `.py`·`.md` 해시와 Git 상태가 동일했고, 제품·테스트 소스의 검토 해시는 현재 파일과 일치한다.

| 범위 | 명령 | 발견/실행/통과 | 실패/오류/skip | 판정 |
| --- | --- | --- | --- | --- |
| HTTP 통합·사용 사례 | `python3 -m unittest discover -s tests -p 'test_http_api.py' -q` | 32/32/32 | 0/0/0 | 통과 |
| 저장소 회귀 | `python3 -m unittest discover -s tests -p 'test_store.py' -q` | 24/24/24 | 0/0/0 | 통과 |
| 합계 | 위 두 명령 | 56/56/56 | 0/0/0 | 3단계 범위 승인 |

테스트 발견 목록·TC 문서의 고유 ID를 프로그램으로 대조해 `TC-03-I-001`~`023` 23개, `TC-03-E-001`~`006` 6개가 모두 대응했다. I-017·E-003·E-005의 추가 경계 메서드 3개를 포함해 HTTP 테스트는 32개다. 위 합계는 runner의 실행 수와 열거된 목록 수에 모두 일치한다. 최종 승인은 `REQ-03-001`~`008`의 HTTP 연결·재사용 및 저장소 회귀에 한정된다. **고정 포트 수동 시연은 미실시**이나 별도 프로세스·임시 포트의 원본 호출 횟수 `0→1→1`과 재시작 흐름은 HTTP 공식 테스트에 포함됐다. TTL·무효화·동시성 방어·영속성·성능 비교는 후속 범위다. 이 기록은 검토된 소스 이후 갱신한 문서이며 제품 코드는 변경하지 않았다.
