# 7단계: 실시간 성능 비교 웹 뷰

- **상태:** 실행·화면 계약 채택, 구현 전 TC 작성 · 로컬 준비·실행 서버 연결 구현과 테스트 이중물 기반 자동 검증(검토 결함 수정 후 47/47) · 실제 Docker·화면·독립 검토 미실행
- **목적:** 브라우저에서 실행 버튼을 눌러 실제 MongoDB 원본 API와 Mini Redis를 이용한 성능 비교를 새로 실행하고, 그 결과를 바로 확인한다. 저장된 측정값만 보여주는 정적 리포트가 아니다.
- **선행 결과:** [6단계 성능 비교 조건·결과](../06-integration-performance/verification.md#3-성능-비교-실행). 이번 웹 뷰의 새 실행 결과를 6단계의 기존 측정 결과와 혼동하지 않는다.
- **실행·화면 계약 채택:** [실행 조건·화면 계약 (execution-screen-contract.md)](execution-screen-contract.md), [D-0008](../../decisions/0008-live-benchmark-contract.md). Docker 기동·필요 시 시드 생성·실행 전 재시작, 정리 버튼 제외, 상세 HTTP·안전 정책을 7단계 구현 기준으로 채택했다.
- **설계 기준:** [로컬 준비·측정 실행 서버와 화면 계약 설계 (design.md)](design.md). 전체 설계 검토는 **조건부 적합**이었고 당시 차단 의견은 수정 후 해당 범위의 제한 재점검에서 **설계 수준 비차단**이다. 수정본 전체의 독립 재승인이나 구현·실행 검증으로 간주하지 않는다.
- **구현 전 검증 계획:** [테스트 케이스 (test-cases.md)](test-cases.md). U 5개·I 17개·E 3개 및 검토 전용 R 3개. 독립 계약 대응 검토는 **조건부**였고 두 차단 지적과 직접 보완을 문서에 반영했다. 수정본의 별도 재점검·테스트 코드/실행은 아직 없다.

## 범위와 완료 기준

- 로컬 시연용 화면에서 **비교 실행 → 진행 상태 → 미사용·미스·히트 결과**를 확인한다. 중앙값·P90, 성공·실패 수와 측정 조건을 함께 표시한다.
- 실행은 기존 `examples/benchmark.py`의 실제 요청 경로·측정 규칙(서로 다른 키, 순차 100회씩, 예열 제외, 값 획득만 측정, 실패 원자료 보존)을 재사용한다. 브라우저에서 잰 시간을 기존 성능 수치처럼 표시하지 않는다.
- 전용 로컬 준비 동작에서 Docker MongoDB 기동·필요 시 시드 생성·실행 전 재시작을 지원한다. 시드는 실행마다 다시 생성하지 않는다. 준비·서버 기동·상태 준비·결과 표시 시간은 측정 구간 밖이다. 기존 원자료를 덮어쓰지 않는다.
- `mini_redis/` 제품 코드와 기존 측정 규칙은 변경하지 않는다. 웹 뷰는 `examples/`의 로컬 시연 기능으로 한정한다. 실제 작동을 확인하기 전에는 완료로 표시하지 않는다.

## 진행 체크리스트

각 항목의 체크는 **해당 산출물과 필요한 실행 근거**를 확인한 뒤에만 한다. TC 문서 작성은 실행 결과가 아니다.

1. [x] **실행 조건·화면 계약 정리** — Docker 기동·시드 생성/확인·재시작의 안전 경계와 실행 요청·상태·결과·오류 형식, 로컬 접근 범위를 [실행·화면 계약 (execution-screen-contract.md)](execution-screen-contract.md)과 [D-0008](../../decisions/0008-live-benchmark-contract.md)에 확정했다. 이는 구현·테스트 통과가 아니다.
2. [x] **구현 전 TC 작성·계약 대응 검토 반영** — [테스트 케이스 (test-cases.md)](test-cases.md)에 정상/실패 경로, 시드 삭제 경계, 기록 선행·교차 checkout 복구, 결과 출처·화면, 실제 Docker 시연을 분리했다. 독립 검토는 조건부였고 차단 지적을 반영했으나 수정본 재점검과 실행은 아직 없다.
3. [ ] **로컬 준비·실행 서버 연결** — 전용 준비 작업과 웹 요청으로 기존 측정기를 실행하고, 중복/겹침 방지·완료/실패 결과·시간 초과 시 프로세스 정리를 구현한다. 완료: Docker·시드·재시작의 준비 상태가 구분되고 새 실행의 원자료가 별도 경로에 남으며 성공·실패가 화면용 응답으로 구분된다. 현재: [구현 기록 (implementation.md)](implementation.md)·[검증 기록 (verification.md)](verification.md)에 이중물·격리 프로세스 기반 결과만 있고 실제 Docker·측정기 실행과 독립 검토가 없어 체크하지 않는다.
4. [ ] **웹 화면 구현** — 실행 버튼, 진행 상태, 세 조건의 중앙값·P90 비교 그래프, 성공·실패 수와 조건·한계를 표시한다. 완료: 정적 예시 수치가 아니라 해당 실행의 실제 결과를 표시한다.
5. [ ] **실제 시연·영향 검증** — 준비 동작으로 MongoDB를 띄우고 시드 점검·필요 시 생성·재시작한 뒤 Mini Redis 경로까지 화면에서 실행해 결과를 원자료와 대조한다. DB 미기동·시드 불일치·실패·연속 클릭·자원 잔존 안내도 확인하며, 변경 영향이 있는 기존 테스트만 선별한다. 완료: 실행 명령, 실제 결과, 오류 처리와 남은 한계를 기록한다.

## 경계

- 이 단계는 **시연 인터페이스 추가**이며 6단계 성능 측정을 소급 변경하지 않는다. 새 실행의 결과는 실행 환경·시점과 함께 따로 기록한다.
- 웹 화면이 직접 DB나 Mini Redis로 교차 출처 요청을 보내거나 브라우저 타이머로 성능을 판정하지 않는다. 로컬 실행 서버가 기존 측정기를 호출하고 화면은 진행·결과 표시를 맡는다.
- Docker 컨테이너·볼륨 삭제용 **정리 버튼/API는 범위 밖**이다. 화면을 닫아도 자원 삭제를 보장하지 않으므로, 남는 자원과 수동 정리 방법을 안내한다. 서버 종료 시 자동 중지·삭제하지 않는 정책은 [상세 계약](execution-screen-contract.md)에서 별도로 채택했다.
- 배포·공개 서비스·동시 부하 측정·시드 생성의 매번 자동화는 이번 범위에 포함하지 않는다. **필요 시 명시적으로 시드를 생성하는 로컬 준비 동작은 범위에 포함한다.**

**다음 행동:** 서버 연결 구현(`examples/live_benchmark.py`, `tests/test_live_benchmark.py`)의 독립 검토와 [검증 기록](verification.md#3-tc별-결과)의 부분 통과·미실행 TC 보완 여부를 정한 뒤 웹 화면 범위를 결정한다. 실제 Docker 시연(E)은 격리 자원 확인 전에는 실행하지 않는다.
