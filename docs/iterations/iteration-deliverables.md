# 단계별 구현·검증 산출물 가이드

- 상태: 운영 초안 — 구현 전 TC 작성 방식 반영, 세부 파일 형식은 진행하며 조정 가능
- 대상: 구현이 있는 각 `docs/iterations/<번호>-<주제>/`
- 근거: [과제 원문](../assignment.md), [프로젝트 컨벤션](../conventions.md#단계별-문서의-최소-단위), [구현 단위 가이드](implementation-units.md), [진행 현황](README.md)

이 가이드는 단계별 **요구사항 정의 → 설계 → 설계 검증 → 구현 전 테스트 케이스(TC) 작성 → 구현 → 구현 검증 및 테스트**의 연결을 유지한다. TC는 검토된 요구사항·설계를 기준으로 구현 전에 문서화하고, 실제 테스트 코드 작성·실행 결과와 구분한다. 문서 작성 자체를 구현·테스트 완료로 간주하지 않는다. 1단계처럼 코드가 없는 범위·계약 단위에는 구현·TC·실행 결과 문서를 억지로 만들지 않는다.

## 문서별 책임과 작성 시점

| 파일 | 작성 시점 | 담을 내용 · 다른 파일과의 경계 |
| --- | --- | --- |
| `overview.md` | 단계 착수부터 | 목표·현재 위치·체크리스트·다음 확인 지점과 산출물 링크. 상세 명세·실행 결과를 반복하지 않는다. |
| `requirements.md` | 설계 전 | 고정 `REQ-<단계>-<일련번호>`, 동작·인수 조건·출처·범위. 실제 통과 여부는 적지 않는다. |
| `design.md` | TC 구체화 전 | 책임 경계·공개 계약·상태와 실패 처리·선택 이유·요구사항 대응. 구현 파일 구조나 실행 결과를 선결정하지 않는다. |
| `test-cases.md` | **설계 검증 후, 구현 전** 작성, 설계 변경 시 갱신 | TC ID, 연결된 REQ ID, 유형, 전제·입력/절차·기대 결과. 설계 특유의 확장·실패 경계도 포함한다. 실제 실행 결과는 여기에 섞지 않는다. |
| `implementation.md` | 실제 코드 작업을 시작할 때 | 변경한 소스·테스트 경로, 구현에서 정한 해시 계산·자료 표현 등 선택, 핵심 연산 흐름, 설계와 달라진 부분·이유. 작성 예정인 파일을 구현 완료로 적지 않는다. |
| `verification.md` | 실제 검토·테스트 실행 시 | TC별 테스트 코드 경로, 명령·환경·실제 결과, 실패·미실행 및 남은 위험. 설계 문서 검토와 코드 실행을 구분한다. |
| `result.md` (필요할 때만) | 단계 마무리 시 | 시연 방법, 완료·미완료 범위와 다음 단위로 넘기는 영향만 요약한다. `implementation.md`·`verification.md`의 상세 내용은 링크로 연결한다. |

모든 파일을 미리 빈 양식으로 만들지 않는다. 해당 작업을 시작할 때 만들고, 작은 단계라면 결과 요약은 `overview.md`에 둔다. 다만 구현 단위의 요구사항은 별도 `requirements.md`, 구현 전 TC는 별도 `test-cases.md`로 유지해 단계 간 추적이 가능하게 한다.

각 단계의 `overview.md`를 **문서 입구**로 삼아 실제 작성된 파일의 역할과 연결 관계를 짧게 안내한다. 진행 체크리스트의 링크는 `검증 기록 (verification.md)`처럼 **역할 (실제 파일명)** 형식으로 표기하고, 동일 파일을 `실행 기록`·`verification.md`처럼 다른 이름으로 혼용하지 않는다. `test-cases.md`는 실행 전 계획이고 `verification.md`는 실행·검토 결과다.

## TC 작성과 실행

1. **구현 전:** 요구사항 ID와 설계의 관찰 가능한 경계를 기준으로 TC 목록을 작성한다. 각 기능 요구가 어느 TC에서 확인되는지 표시한다. 테스트가 어려운 설명·코드 검토 항목은 검증 방식도 구분한다.
2. **유형:** `U`(단위: 저장소 등 한 책임 경계), `I`(통합: HTTP 처리부+실제 저장소 등 연결부), 필요하면 `E`(종단 간 사용 사례)를 구분한다. ID 제안은 `TC-02-U-001`, `TC-03-I-001`처럼 단계·유형·일련번호 조합이다. 한 번 부여한 ID는 이름이나 순서가 바뀌어도 재사용·재번호화하지 않는다.
3. **케이스의 최소 항목:** `TC ID`, `유형`, 연결된 `REQ ID`(과제의 품질 항목처럼 별도 ID가 없으면 근거 문서), **전제 상태**, **입력/절차**, **기대 결과**, 자동화 예정 여부 또는 검증 방식. 오류라면 기대 예외와 기존 상태 보존 범위를, 시간·동시성이 필요하면 제어 조건과 기대 최종 상태를 적는다. 구현 내부 함수를 호출하도록 미리 강제하지 않는다.
4. **구현 중:** TC 전체를 한꺼번에 자동화한 뒤 코드를 일괄 작성하기보다, 관찰할 동작 하나씩 **테스트 작성 → 의도한 이유로 실패 확인(RED) → 최소 구현 → 통과 확인(GREEN) → 정리**를 반복한다. 테스트가 단순한 import 오류·오타로 실패하면 바로잡고 다시 확인한다. 새 경계가 발견되면 TC·설계를 함께 갱신한다.
5. **실행 후:** 실제 테스트 함수·명령과 결과를 `verification.md`에서 TC ID에 연결한다. 실행하지 않은 TC는 `미실행`, 실패한 TC는 `실패`로 남긴다. 계획한 TC가 있다는 사실만으로 인수 조건을 충족했다고 표시하지 않는다.

`test-cases.md`의 한 행 예시(아직 실제 TC 채택·실행 기록이 아님):

| TC ID | 유형 | 요구사항 | 전제·입력/절차 | 기대 결과 | 검증 방식 |
| --- | --- | --- | --- | --- | --- |
| `TC-02-U-001` | 단위 | `REQ-02-002` | 빈 저장소에 `set("k", "")` 후 `get("k")` | `(True, "")` | 자동화 예정 |

## 단계에 따른 테스트 경계

- **2단계:** HTTP 없이 저장소의 기본 연산·충돌·부하율 경계·재배치·잘못된 입력·저장 실패 보존을 단위 TC로 다룬다. 직접 구현 제약은 테스트만으로 충분하지 않으므로 코드 경로 검토도 기록한다.
- **3단계:** HTTP 경로가 저장소에 연결되면 실제 저장소를 사용해 요청·응답과 API 응답 재사용 사례를 통합 TC로 확인한다. 저장소 단위 테스트를 그대로 유지한다.
- **4~5단계:** 만료·무효화, 동시성의 새 상태 변경 경로는 해당 단위의 단위 TC와 기존 연결부의 통합 TC를 함께 확인한다. 동시성은 기대 최종 상태와 동기화 조건을 명시한다.
- **6단계:** 누적 기능의 종단 간 회귀와 과제의 캐시 사용·미사용 성능 비교를 실제로 수행한다. 성능 결과에는 동일 요청·데이터·환경 및 미스·히트 조건과 한계를 적는다.

모든 단위에 단위·통합·종단 간 TC를 형식적으로 채우지 않는다. **새 연결부가 생길 때 통합 테스트를 추가**하고, 마지막 단위에서 전체 흐름을 다시 검증한다.

## 구현·검증 기록의 최소 형식

`implementation.md`는 실제 변경이 생긴 뒤 다음을 기록한다.

- **상태·근거:** 적용한 요구사항/설계/TC 링크, 구현 중 또는 구현 완료 여부.
- **변경 경로와 역할:** 실제 소스·테스트 파일 경로와 각 파일의 책임. 파일별 수정 일지는 필요 없다.
- **핵심 로직:** 입력→처리→출력과 구현에 위임된 선택(예: 해시 계산 규칙), 설계 계약과 다른 점·영향.
- **실행 방법:** 실제로 확인한 명령만 기록하고, 테스트 판정은 `verification.md`로 연결한다.

`verification.md`는 설계 검토, 테스트 실행 및 결과를 분리한다. 실행 표는 최소한 다음 항목을 가진다.

| TC ID 또는 검토 대상 | 유형·테스트 코드 경로 | 실행 명령·환경 | 기대 결과 | 실제 결과·상태 | 남은 문제 |
| --- | --- | --- | --- | --- | --- |
| 해당 작업에서 채움 | 단위/통합/종단 간/코드 검토 | 실제 실행 뒤 채움 | TC 링크 또는 요약 | 통과·실패·미실행·차단을 구분 | 재현 조건·후속 조치 |

성공·실패의 실제 관찰과 명령을 적고, 문서 검토를 실행 테스트 통과로 바꾸지 않는다. 단계 종료 시 `overview.md`와 [전체 진행 현황](README.md)에는 상태와 근거 링크만 갱신한다.
