# 2단계 구현 — 해시 테이블 저장소

- 상태: 구현 작성, 전체 단위 TC 통과·독립 검토 승인 ([검증 기록 (`verification.md`)](verification.md))
- 근거: [요구사항](requirements.md), [설계](design.md), [구현 전 TC](test-cases.md), [검증 기록 (`verification.md`)](verification.md)

`mini_redis/store.py`의 `HashTableStore`는 HTTP와 분리된 순차 호출용 저장소다. 기존 `tests/test_store.py`의 임시 클래스·내부 관찰 접점을 구현에 맞춰 사용한다. 공개 연산은 `set`, `get`, `exists`, `delete`이며 입력 검증 뒤 키를 해시해 버킷 체인에서 전체 키를 비교한다.

해시는 유니코드 코드 포인트를 순서대로 처리하는 64비트 다항식(`h = (31*h + ord(char)) mod 2^64`)이다. 버킷은 리스트의 리스트이며 각 항목은 `(키, 값)` 튜플이다. 새 키로 부하율이 1을 초과할 때 새 버킷 배열을 두 배로 만들어 재배치하고, 삭제 후 축소하지 않는다.

저장 실패 보존을 위해 덮어쓰기·일반 삽입은 대상 체인을 복사한 뒤 수정하고 마지막에 반영한다. 확장은 별도 배열에 기존 항목과 새 항목을 모두 준비한 뒤 배열을 교체한다. 준비 중 동기 예외가 나면 공개 상태를 건드리지 않고 예외를 전달한다. 항목 수의 새 값도 확정 전에 계산한다. 삭제는 해당 체인에서 항목을 제거한다. 설계 계약과 다른 공개 동작은 없다.

별도 의존성·HTTP 계층·TTL·동시성 기능은 추가하지 않았다. 실제로 확인한 Python 명령과 한계는 [검증 기록 (`verification.md`)](verification.md)에 적는다.
