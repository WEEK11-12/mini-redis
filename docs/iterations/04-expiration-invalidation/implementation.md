# 4단계 구현 기록 — 만료와 무효화

- 상태: 구현 완료, 제한 독립 재검토 통과 ([검증 기록](verification.md), 2026-11-18)
- 기준: [요구사항](requirements.md), [설계](design.md), [구현 전 TC](test-cases.md)

## 변경 경로

- `mini_redis/store.py`: 항목 `(키, 값, 선택적 기한)`과 주입 가능한 단조 나노초 시간원. 기존 연산은 만료를 미존재로 처리하고 접근 시 물리적으로 제거한다. `set_ttl`은 현재 시각 기준 정수 나노초 기한을 설정·갱신하고 `clear_ttl`은 값은 남기고 기한만 지운다. `sweep_expired`는 미접근 만료 항목을 순회·제거한다. 변경과 제거는 버킷 복사본을 먼저 만든 뒤 교체하여 동기 예외 시 기존 버킷·항목 수를 유지한다. 일반 `set`은 TTL을 해제한다.
- `mini_redis/http_api.py`: 기존 JSON 본문 크기·프레이밍 검증을 재사용해 `/keys/{key}/ttl`의 PUT·DELETE를 연결한다. JSON 정수는 런타임 자릿수 제한과 무관하게 정수로 해석한다. 기존 순차 서버의 `service_actions`에서 요청 사이 1초 목표 간격으로 유휴 정리를 수행하고, 정리 예외·진단 출력 예외는 요청과 분리한다.
- `tests/test_expiration_store.py`: 카운터 감소 연산 실패를 주입해 만료 접근·정리·일반 삭제의 커밋 전 상태 보존과 재시도를 검증한다.

별도 정리 스레드, 새로운 CLI 설정, 동시성 방어, 영속성은 추가하지 않았다. 물리 항목 수를 부하율에 포함하며 정리 뒤 자동 축소하지 않는다. 값 저장과 TTL 지정은 별도 요청이다.

## 실행

저장소 루트에서 `python3 -m unittest discover -s tests -p 'test_expiration*.py' -q`로 새 계약의 현재 실행 테스트를 확인한다. 실행 결과와 미확인 조건은 [검증 기록](verification.md)에 분리한다.
