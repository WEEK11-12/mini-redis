# 7단계: 키·값 인터랙티브 캐시 시연 페이지

- **상태:** 구현 완료. 7단계 시험 30개 통과(8.569s), UI 직접 영향 시험과 실제 브라우저·360px·키보드 확인을 마쳤다. 선별 검증을 수행했고, 그 지적은 세 수정의 한정 재검토에서 통과했다. 폐기한 7단계 정리 영향 검토도 해당 범위에서 통과했다. 합의한 로컬 시연 범위에서 단계 마감을 완료했다. 실제 MongoDB 장애는 미실행 한계로 기록하되 별도 인수 기준으로 추가하지 않는다. 근거는 [검증 결과·TC 증거·한계](verification.md).
- **목적:** 브라우저에서 키와 값을 입력해 저장·수정하고, 키별로 값을 읽어 오면서 **캐시에서 읽었는지 DB에서 읽었는지**와 걸린 시간을 확인한다. 사용자에게는 일반적인 저장·조회 화면으로 보이며, 내부에서는 DB와 Mini Redis 캐시를 모두 사용한다. 소요 시간은 기록으로 남는다.
- **이전 후속 시연과의 관계:** 버튼 한 번으로 고정 조건 비교 측정을 실행하던 실시간 성능 비교 웹 뷰는 의도와 달라 폐기했고, 그 전용 코드·시험·문서는 사용자 요청으로 정리했다. 이 단계의 직접 입력형 화면은 그 코드에 의존하지 않는다. 6단계의 측정 도구(`examples/benchmark.py`·`seed_mongo.py`)와 성능 기록은 그대로 남아 있다.
- **요구사항:** [요구사항 명세 (requirements.md)](requirements.md) — `REQ-07-001`~`013`

2. [x] **설계 초안 간소화** — [설계 (design.md)](design.md)에 전용 자식 1회 기동, 실패 시 캐시 중단·DB 대체 읽기, 저장·기록·로컬 보호를 정리했다. 이 개정의 별도 복잡한 설계 검토는 생략하며, 구현·실행 검증 통과를 뜻하지 않는다.
3. [x] **구현 전 TC 작성** — 요구사항 ID에 연결한 [TC 계획 (test-cases.md)](test-cases.md) 작성. 계획과 실행 결과는 분리하며 일부 실행 결과는 [검증 기록 (verification.md)](verification.md) 참조.

## 경계

- 삭제 버튼, TTL 입력, 동시 다중 사용자, 인증·배포, 공식 성능 측정은 이번 범위 밖이다. 화면의 속도 기록은 단발 체험 수치이며 6단계 성능 비교와 같지 않다.
- `mini_redis/` 제품 코드는 바꾸지 않는다. 시드 컬렉션과 기존 데이터는 건드리지 않는다.

**현재 판단:** 구현은 완료했고, 세 수정 범위의 잔여 필수 결함은 독립 한정 재검토에서 확인되지 않았다. 합의한 로컬 시연 범위의 구현·검증 기록 정리와 단계 마감을 완료했다. 실제 MongoDB 장애 시험은 미실행 한계이지 추가 인수 조건이 아니다. 늦은 DB 반영은 수용된 한계, 엄격한 OS 소유 증명·고아 자동 회수는 범위 제외다.
