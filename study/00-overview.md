### Redis 이해를 위한 학습 목차


**[1. Redis는 왜 등장했나 (역사와 배경)](./01-background.md)**

- 디스크 기반 DB의 한계: 반복되는 조회, 디스크 I/O 비용
- 캐시의 등장: 자주 쓰는 데이터를 메모리에 `키 → 값`으로 저장 (Memcached)
- Memcached의 한계: 구조 없는 값, 디스크 저장 불가, 일부만 수정하기 어려움
- Redis의 탄생(2009): 메모리 속도 + 서버가 이해하는 자료구조 + 선택 가능한 영속성
- 이후의 흐름: 캐시를 넘어 세션, 랭킹, 큐 등으로 확장, DB와의 공존

**[2. 언제, 어떻게 Redis를 쓰나](./02-when-to-use.md)**

- 대표 사용처: 캐시, 세션, 조회수/카운터, 랭킹, 인증번호(TTL), 요청 제한
- 서비스 구조에서의 위치: 앱 서버 ↔ Redis ↔ DB
- 캐시 연동 방식: Cache-Aside(앱이 직접 처리)와 Read-Through
- Redis가 맞지 않는 경우: 복잡한 조회/조인, 메모리보다 큰 데이터

**[3. 사용자가 실제로 쓰는 기능 (구현 범위 정하기)](./03-how-to-use.md)**

- 기본 명령: SET, GET, DEL, EXISTS
- 만료 시간(TTL): EX, EXPIRE, TTL
- 자료구조와 편의: String, List, Hash, Set, Sorted Set
- 원자적 명령: INCR 등 "읽고-계산하고-쓰기"를 한 번에
- 접속 방식: `redis-cli`, 언어별 클라이언트 라이브러리
- 직접 체험하기: Redis를 설치하고 명령어 실행, 만료 동작 확인
- 정리하기: Mini Redis에서 어디까지 구현할지 범위 결정

**[4. 해시 테이블 설계와 구현 (과제의 핵심)](./04-hash-table.md)**

- 왜 O(1)인가: 순차 탐색 O(N)과 해시 조회 비교
- 해시 함수: 키를 배열 위치로 바꾸는 방법과 좋은 해시 함수의 조건
- 충돌 처리: 체이닝과 오픈 어드레싱, 각각의 트레이드오프
- 리사이징: 부하율(load factor), 테이블 확장과 재해싱
- 주요 함수의 동작: put(set), get, delete, 키 갱신
- 설명할 수 있어야 하는 것: 설계 원리, 구현 과정, 함수별 동작 방식
- 참고: Redis `dict`의 점진적 리해싱

**[5. 만료와 무효화](./05-expiration-invalidation.md)**

- 만료 시간 저장 방식: 만료 시각(타임스탬프) vs 남은 시간
- 만료된 값을 요청받았을 때의 처리: Lazy 삭제(조회 시 확인)
- 만료된 키의 메모리 정리: Active 삭제(주기적 정리)와 트레이드오프
- 데이터 무효화(deprecated): 명시적 삭제 API와 TTL
- 캐시와 원본 DB의 불일치 문제
- 엣지 케이스: 만료 직전 조회, TTL 갱신, 만료 후 같은 키 재저장

**[6. 동시성 구조](./06-concurrency.md)**

- 경쟁 상태(race condition): 조회수 증가 예시
- Redis의 방식: 싱글 스레드 이벤트 루프와 I/O 멀티플렉싱
- 멀티 스레드 방식: 뮤텍스, 읽기/쓰기 락과 락의 비용
- 원자성 보장: 명령 단위의 순차 처리
- 만료 정리 같은 백그라운드 작업과의 충돌
- Mini Redis의 구조 선택: 순차 처리 vs 락 기반

**[7. 외부 인터페이스(API) 설계](./07-interface-design.md)**

- 개발자에게 제공되는 형태: 서버 접속 + 명령 전송
- 인터페이스 선택: HTTP REST API vs TCP 서버
- API 설계: 저장, 조회, 삭제, 남은 시간 조회
- 요청/응답 형식과 상태 코드: 없는 키, 만료된 키, 잘못된 요청
- 사용하는 쪽에서 본 편의성: 클라이언트 예시 코드

**[8. 서버 다운 대비: 영속성 (Optional)](./08-persistence.md)**

- 메모리 저장소의 약점: 서버가 꺼지면 데이터가 사라짐
- RDB: 주기적 스냅샷, 구현이 쉽지만 마지막 시점 이후 유실 가능
- AOF: 쓰기 명령 로그 누적, 재시작 시 재실행으로 복구
- 트레이드오프: 안전성, 성능, 구현 난이도
- 복구 시 만료된 데이터 처리

**[9. 테스트와 성능 비교](./09-testing.md)**

- 단위 테스트: 저장, 조회, 삭제, 만료, 충돌, 리사이징
- 기능 테스트: 간단한 API를 만들고 응답 값을 Mini Redis에 저장해 활용
- 엣지 케이스 정리: 없는 키, 빈 값, 동일 키 덮어쓰기, 동시 요청, 만료 경계
- 성능 비교: Redis(캐시) 사용 전/후 응답 시간 측정 방법
