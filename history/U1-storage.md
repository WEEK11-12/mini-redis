# U1 — 저장·조회·삭제 구현과 검증 기록

기록 작성 당시 상태: U1 구현·테스트와 사용자 연결 보존 이해 확인 완료. 통합 커밋 92c5bc0으로 개인 main에 반영했다. 아래 실행 과정은 당시 기록이며 현재 진행 상태는 WORKLOG를 따른다.

## 목적과 합의

관련 요구: R-01, R-02, R-11. 테스트: T-01~T-06. 문자열 저장·덮어쓰기·조회·삭제와 충돌 목록의 연결 보존을 확인한다. 사용자와 기대 동작·테스트를 먼저 합의했다. 없는 키 조회는 None, 삭제는 bool이다.

첫 구현의 배치 결정은 AI가 다음처럼 정했다. 기존 동작 정책을 바꾼 것이 아니며 더 큰 추상화가 필요하면 해당 단위에서 검토한다.

- `mini_redis/store.py`: FNV-1a, 연결 노드, 저장소와 공용 Lock을 최소 파일 하나에 배치.
- `tests/test_store.py`: 표준 unittest 사용. 설치된 Python 3.13.14로 추가 패키지 없이 실행.
- `MiniRedisStore.set(key, value)`는 반환값 없이 완료한다. HTTP의 ok 응답과 내부 함수의 반환값을 구분한다.
- `get(key)`는 문자열 또는 None, `delete(key)`는 bool, `len(store)`는 현재 저장된 키 수를 반환한다.
- `.gitignore`: Python 캐시와 향후 가상환경을 Git에서 제외한다.

## 1. 먼저 테스트를 실행

명령: `python -m unittest discover -s tests -v`

호출 가능한 빈 함수에 NotImplementedError를 둔 뒤 실행했다. 6개 테스트가 실행됐고 하위 사례를 포함해 8개 오류가 발생했다. 종료 코드는 1이다. 원인은 함수 미구현이며 설치·import 오류가 아니었다.

이 결과는 테스트 실행 준비의 증거다. 실제 저장소 버그를 발견했다거나 테스트의 검출력을 모두 증명했다고 해석하지 않는다.

## 2. 최소 구현

저장소에는 16개 버킷의 리스트, 키 개수, Lock 하나를 둔다. 노드는 key·value·next를 가진다. Python dict로 저장소를 대체하지 않았다.

```text
set: 락 → UTF-8 키 해시 → 버킷 → 실제 키 비교
     같은 키면 값 교체, 없으면 목록 앞에 새 노드 연결 → 락 반환
get: 락 → 같은 경로로 탐색 → 값 또는 None → 락 반환
delete: 락 → 이전 노드와 현재 노드를 추적
        앞/중간/끝의 연결을 고치고 키 수 감소 → bool → 락 반환
```

덮어쓰기는 노드를 추가하지 않으므로 키 개수를 늘리지 않는다. with 문으로 함수가 return하거나 예외가 나도 락을 돌려준다. 내부 보조 함수는 락을 다시 획득하지 않는다.

## 3. 재실행 결과

같은 명령의 종료 코드는 0, `Ran 6 tests` / `OK`다.

| ID | 실제 확인 | 결과 |
| --- | --- | --- |
| T-01 | 저장한 문자열과 키 개수 | PASS |
| T-02 | 덮어쓴 최신 값, 키 개수 1 유지 | PASS |
| T-03 | 삭제 True, 이후 None, 키 개수 0 | PASS |
| T-04 | 없는 키 조회 None·삭제 False, 기존 데이터 보존 | PASS |
| T-05 | 충돌한 세 키 각각 조회, 중간 키 덮어쓰기 시 다른 값 보존 | PASS |
| T-06 | 새 목록마다 세 키 각각 삭제, 나머지 값·키 개수 보존, 재삭제 False | PASS |

충돌 입력은 a·q·A다. 16버킷에서 모두 12번에 들어간다. 단일 ASCII 바이트의 하위 4비트가 모두 1이므로 독립 계산 `((5 XOR 1) * 3) % 16 = 12`와 대조했다. 전체 FNV 알려진 벡터 검증은 U2에 남아 있다.

현재 삽입은 앞에 붙이므로 목록은 A → q → a다. 각 키를 따로 삭제해 첫·중간·끝을 모두 확인했다. 테스트 자체는 세 위치를 특정 키에 고정하지 않아 삽입 순서 변경에도 같은 보존 조건을 검사한다.

## 4. 테스트가 잘못된 삭제를 잡는지 실험

제품 파일을 바꾸지 않고 unittest.mock.patch로 실행 중 delete만 잠시 교체했다. 정상 삭제 뒤 해당 버킷을 통째로 비우는 고장 동작을 넣었다. T-06의 세 삭제 사례가 모두 남은 키 조회에서 assertion 실패했다. 예외나 실행 환경 오류가 아니라 기대 결과 불일치였다.

실험은 실패를 예상하고 실패 검출 여부를 검사하는 방식으로 종료 코드 0이었다. 대체 함수를 해제한 뒤 정상 테스트를 다시 실행한다. 제품에 그런 버그가 있었다는 뜻이 아니며 수정 이력으로 꾸미지 않는다.

## U1 완료 당시 남은 범위와 다음 논의

아래는 U1 당시 상태다. 현재 입력 검사·확장은 [U2 기록](U2-input-and-resize.md)에서 구현·검증했다. TTL 이후는 여전히 남아 있다.

- U1 실제 구현에서 발견한 제품 버그: 현재 없음. 따라서 버그 수정 내역도 없음.
- 입력 형식·길이 검사와 확장은 아직 없다. 버킷은 16개 고정이며 다음 U2에서 합의한 정책을 구현한다. 공개 서버로 사용하지 않는다.
- TTL·청소·HTTP 서버는 아직 없다. Flask·Waitress도 이번에 설치하지 않았다.
- 락은 코드에 적용했지만 실제 동시 실행의 검증은 아직 안 했다. 순차 테스트 통과를 동시성 보장으로 확대하지 않는다.
- 부하·스트레스·성능 비교는 미실행이다. 큰 데이터를 넣고 성능을 주장하지 않는다.
- 사용자는 중간 노드 삭제 시 앞 노드가 다음 노드를 가리켜야 함을 설명하고 다음 단위 진행을 요청했다. U2는 입력·해시 검산·확장을 다룬다.
