# U2 — 입력 검사·해시 검산·확장

기록 작성 당시 상태: 로컬 구현·테스트 완료, 사용자와 결과 확인 대기. 이번 변경의 커밋·푸시는 하지 않았다. 관련 요구 R-01·R-03·R-04·R-09, 테스트 T-07~T-09.

## 진행 전 구조 검토

README·문서 지도·인계와 U1 코드·테스트를 대조했다. U1의 실제 저장·탐색·삭제·키 개수·공용 락에서 다음 단위를 막는 결함을 찾지 못했다. 입력 제한·확장·TTL이 없다는 것은 명시된 후속 범위다. 전체 시스템 안정성을 증명한 검토는 아니다.

문서에는 이미 92c5bc0으로 푸시한 U1을 미커밋으로 표시하거나 사용자 검토 대기로 표시한 오래된 내용이 있었다. 현재 상태로 수정하고 tests/의 자동 검사와 history/의 읽기용 기록을 구분했다. 검토 후 기존 테스트 6개, 문서 22개·상대 링크 124개·요구 ID 13개·테스트 ID 16개 검사를 통과한 뒤 U2를 시작했다.

## 합의와 테스트 입력

문자열 외 키·값은 TypeError, UTF-8 길이 초과는 ValueError로 알리는 규칙을 사용자가 확정했다. HTTP의 400·413 등으로 변환하는 작업은 아직 하지 않는다.

| ID | 입력·경계 | 기대 결과 |
| --- | --- | --- |
| T-07 | 빈 키·값, 원문 공백·한글·줄바꿈 | 그대로 저장·조회 |
| T-07 | None·숫자·bool·bytes·list·dict 키, 문자열 외 값 | TypeError, 기존 값·키 개수 유지 |
| T-07 | UTF-8 키 1,024바이트와 1,025바이트 | 전자는 허용, 후자는 모든 키 연산에서 ValueError |
| T-07 | UTF-8 값 1,048,576바이트와 1바이트 초과 | 전자는 허용, 후자 덮어쓰기는 거부·이전 값 보존 |
| T-08 | FNV-1a 64비트 기준 벡터 4개 | 문서의 고정 기대값과 일치 |
| T-09 | 12개 저장 후 13번째 신규 키 | 16 → 32버킷, 13개 값 보존 |
| T-09 | 12개 상태의 덮어쓰기·잘못된 신규 입력 | 확장하지 않음, 정확한 키 개수·기존 값 유지 |
| T-09 | 65개 삽입으로 반복 확장 후 갱신·전체 삭제 | 128버킷, 모든 값 유지, 삭제 후 키 개수 0 |

버킷 수 검사는 내부 정책 R-04의 검증이므로 테스트에서 _buckets 길이를 확인한다. HTTP 응답에 내부 배열을 노출하는 기능을 추가하지 않았다. 65개는 확장 경계를 넘기는 작은 정확성 테스트이며 부하 테스트가 아니다.

## 실제 실행과 수정

명령: `python -m unittest discover -s tests -v`.

테스트 10개를 먼저 추가한 뒤 변경 전 코드를 같은 unittest 로더로 실행했다. 전체 16개 테스트에서 하위 사례를 포함해 assertion 실패 13개·오류 18개, 종료 코드 1이었다. 전체 로그는 로컬 상위 .tmp/u2-before-implementation.log에 보관했다.

- 길이 초과와 문자열 아닌 값이 거부되지 않았다.
- 문자열 아닌 키는 기대한 TypeError 대신 encode 호출에서 AttributeError가 났다.
- 13번째 키·반복 삽입에서 고정 16버킷이 그대로였다.
- 기존 FNV 함수의 기준 벡터와 U1은 이미 통과했다.

위 결과는 U2에서 구현할 미완성 범위를 드러낸 것이며 U1의 합의된 정상 문자열 동작이 회귀한 것은 아니다.

### 보완한 코드

1. set/get/delete가 문자열과 UTF-8 길이를 검사한다. set은 키·값 검사 모두 끝나야 락을 잡고 변경한다.
2. 기존 키를 먼저 찾고 덮어쓰기는 즉시 완료한다. 신규 키만 `(키 수 + 1) * 4 > 버킷 수 * 3`으로 확장 여부를 판단한다. 이는 0.75 경계를 정수로 비교한 것이다.
3. 새 버킷 배열과 연결 노드를 준비한 뒤 기존 키·값을 재배치하고 테이블을 교체한다. 새 크기로 버킷 위치를 다시 계산한다.

기존 노드의 next를 직접 바꾸며 옮기는 방법은 추가 노드 메모리를 덜 쓴다. 이번 구현은 새 노드를 준비하는 동안 기존 체인을 유지하는 쪽을 택했다. 값 문자열을 복사하는 것이 아니라 같은 불변 문자열을 참조하지만 일시적으로 노드 메모리가 더 필요하다. 모든 메모리 고갈 상황에서 복구된다는 보장은 검증하지 않았다.

구현 후 같은 명령의 결과는 `Ran 16 tests` / `OK`, 종료 코드 0이다. U1 6개와 U2 10개가 함께 통과했다. 구현 후 별도의 추가 버그 수정은 발생하지 않았다.

## FNV 기대값 출처

[IETF FNV 초안 25의 6.2절 Test64](https://www.ietf.org/archive/id/draft-eastlake-fnv-25.html#section-6.2)에 수록된 FNV64svalues를 고정 기대값으로 사용했다. 빈 입력, a, foobar, 제어·상위 바이트를 포함한 Hello! 입력 4개다. 실행한 함수의 결과로 기대값을 생성하지 않았다. 초안 자료이며 최신 표준이라고 설명하지 않는다.

## 남은 범위

TTL·청소·커서, 실제 동시 요청, Flask·Waitress 연결·오류 변환, 부하·성능·메모리 고갈은 미검증이다. 잘못된 Unicode나 극단적인 TTL의 상세 API 응답은 후속 단위에서 논의한다. 다음 U3의 시간 표현·TTL 최대 범위·이미 만료된 키 삭제 반환값은 사용자와 정한 뒤 구현한다.
