# U3 — TTL 저장과 접근 시 만료

기록 작성 당시 상태: 로컬 구현·테스트 완료, 핵심 코드와 결과 사용자 검토 대기. 커밋·푸시 미실행. 관련 요구 R-02·R-05·R-09·R-11, 테스트 T-10.

## 합의한 동작

- TTL은 기간 상한 없는 양의 정수 밀리초다. bool·문자열·소수·null은 정수가 아닌 입력, 0·음수는 잘못된 값으로 거부한다.
- 생략은 무기한, 일반 덮어쓰기는 TTL 제거, TTL 포함 덮어쓰기는 새 저장 시점부터 계산한다. 잘못된 입력은 이전 값과 만료 시각을 유지한다.
- 현재 시간 >= 만료 시각이면 조회는 None. 노드가 남아 있어도 삭제는 False를 반환하고 노드를 제거한다.
- len(store)는 보관 중인 노드 수다. 만료 후 청소·접근 전인 노드도 포함하며 전체 만료 탐색을 하지 않는다.
- 청소 스레드는 아직 없다. 이번 단위는 저장·조회·삭제 시 만료만 다룬다.

사용자는 만료와 청소 완료의 차이를 확인했다. 청소가 삭제했는데 노드가 남은 것이 아니라 청소가 아직 해당 키를 검사하지 않은 상태다. 그래서 사용할 수 없는 키의 delete는 False로 정했다.

## 구현 형태와 이유

- tests/test_ttl.py의 FakeClock으로 정수 나노초를 전달한다. 실제 대기 없이 만료 직전·같음·직후를 재현한다.
- 실제 기본 시간원은 time.monotonic_ns다. TTL 밀리초에 1,000,000을 곱해 정수로 계산한다. 큰 TTL에서 float 변환에 의한 손실을 피한다. 실제 시계 해상도가 1ns라는 뜻은 아니다.
- 노드의 expires_at_ns가 None이면 무기한이다. 입력의 명시적인 ttl_ms=None은 거부한다. 함수 기본값을 별도 _UNSET으로 두어 생략과 null을 구분한다.
- get의 만료 제거와 delete가 같은 _unlink를 사용한다. 첫·중간·끝 연결과 키 개수 변경을 한곳에서 유지하며 호출자는 이미 공용 락을 가지고 있다. 내부에서 락을 다시 잡지 않는다.
- 리해싱 때 값뿐 아니라 expires_at_ns도 복사한다. 일반 덮어쓰기와 새 TTL 덮어쓰기는 기존 노드를 재사용하며 키 개수는 유지한다.

[Python 단조 시간 문서](https://docs.python.org/3/library/time.html#time.monotonic_ns)를 확인했다. 시간 함수의 기준점은 날짜가 아니라 경과 시간 비교에 사용한다.

검사한 입력은 만료 직전/정확한 경계/직후, 무기한, TTL 제거·재설정, 잘못된 TTL 뒤 이전 값·시각 유지, 만료 키 삭제 False와 노드 회수, 유효 키 삭제 True, 만료 잔여 노드 수, 만료 키 재저장·확장 중 TTL 보존, 10의 100제곱 밀리초다.

만료 삭제는 충돌한 세 키를 각각 지워 첫·중간·끝 연결 보존을 확인한다. 큰 TTL은 정수 경계 계산 검증일 뿐 그 기간을 실제 기다린 실험이 아니다.
